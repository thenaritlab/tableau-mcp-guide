# 4.3 วิเคราะห์ข้ามหลาย Data Source

> ระดับ: 🟡 Intermediate

ความสามารถที่ dashboard ปกติทำได้ยาก แต่ MCP ทำได้เป็นธรรมชาติ: **query หลาย data source ในบทสนทนาเดียวแล้วให้ AI เชื่อมผลให้**

## หลักการทำงาน

VDS query ได้ทีละ data source — การ "วิเคราะห์ข้าม" จึงไม่ใช่ join ระดับ database แต่คือ:

```
query DS ตัวที่ 1 → ได้ผลชุด A
query DS ตัวที่ 2 → ได้ผลชุด B
Claude เอา A + B มาเทียบ/รวม/คำนวณต่อในหัวมันเอง
```

เข้าใจข้อนี้แล้วจะรู้ทั้งจุดแข็ง (ยืดหยุ่นมาก) และข้อจำกัด (ต้องระวังเรื่อง granularity + ปริมาณ)

## Use Case 1: เทียบ Actual vs Target

ข้อมูลเป้าอยู่คนละ data source กับยอดจริง — สถานการณ์สุดคลาสสิก:

```
1. จาก "Sales_Actual" query ยอดขายจริงรายเดือน ปี 2026
2. จาก "Sales_Target" query เป้ารายเดือน ปี 2026
3. ทำตาราง: เดือน | จริง | เป้า | ผลต่าง | %achievement
4. เดือนไหนต่ำกว่า 90% ให้ flag 🔴
```

**เคล็ดลับ:** สั่งเป็นขั้นตอนแบบนี้ชัด ๆ ดีกว่าถามรวบ "เทียบยอดกับเป้าหน่อย" — AI จะได้ไม่เดาว่าเป้าอยู่ที่ไหน

## Use Case 2: เชื่อมข้อมูลคนละระบบ

ยอดขาย (จาก ERP) + ข้อมูลลูกค้า (จาก CRM) publish แยกกัน:

```
จาก "CRM_Customers" ดึงรายชื่อลูกค้า segment "Enterprise"
แล้วเอารายชื่อนั้นไป filter ใน "Sales_2026"
สรุปว่าลูกค้า Enterprise สร้างยอดกี่ % ของทั้งหมด
```

⚠️ **เงื่อนไขสำคัญ: key ต้องตรงกันจริง** — ถ้า CRM เก็บ "บจก.สยาม เทรดดิ้ง" แต่ ERP เก็บ "Siam Trading Co." AI จับคู่ไม่ได้ (หรือแย่กว่า: จับคู่ผิดแบบเนียน ๆ) — ปัญหา master data แบบนี้ MCP ไม่ได้แก้ให้ แค่ทำให้เห็นชัดขึ้น

## Use Case 3: ตรวจสอบความสอดคล้อง (Data Reconciliation)

ใช้ MCP เป็นผู้ตรวจ:

```
ยอดขายรวมเดือน ก.ค. 2026 จาก "Sales_Detail" กับ "Finance_Summary"
ตรงกันไหม ถ้าไม่ตรง ต่างกันเท่าไหร่ และลองแตกรายวันดูว่า
ผลต่างกระจุกอยู่วันไหน
```

งานกระทบยอดที่ปกติกินเวลาครึ่งวัน เหลือไม่กี่นาที — และทำซ้ำได้ทุกเดือนด้วย prompt เดิม

## ข้อควรระวัง

### 1. Granularity ไม่ตรงกัน
DS หนึ่งเก็บรายวัน อีกตัวรายเดือน — สั่งให้ชัด: "aggregate ตัวรายวันเป็นรายเดือนก่อนเทียบ" ไม่งั้น AI อาจเทียบผิดระดับ

### 2. ปริมาณข้อมูลข้าม DS
การ "เอารายชื่อจาก DS แรกไป filter DS ที่สอง" ใช้ได้ดีเมื่อรายชื่อไม่กี่สิบ-ร้อยรายการ ถ้าเป็นหมื่นรายการ = filter ยาวเกิน อาจต้องกลับไปแก้ที่ต้นทาง (blend/join ใน Tableau Prep แล้ว publish รวม)

### 3. นิยาม metric ไม่ตรงกันระหว่างระบบ
"ยอดขาย" ใน ERP รวม VAT, ใน Finance ไม่รวม — ก่อนเทียบให้ถาม AI ว่าแต่ละ DS นิยาม field อย่างไร (`read-metadata` ช่วยได้ถ้าใส่ description ไว้ดี)

## แล้วเมื่อไหร่ควร "รวมที่ต้นทาง" แทน?

MCP วิเคราะห์ข้าม DS เหมาะกับงาน **ad-hoc / สำรวจ / กระทบยอด** แต่ถ้าพบว่า:

- ถามคู่ DS เดิมซ้ำ ๆ ทุกสัปดาห์
- ต้อง join กันระดับ transaction ล้านแถว
- ผลลัพธ์ต้องขึ้น dashboard ให้คนอื่นดูด้วย

→ ถึงเวลาทำ data source รวมจริง ๆ (Tableau Prep / SQL view) แล้วให้ MCP query ตัวรวมแทน — เร็วกว่า แม่นกว่า และคนกับ AI ใช้เลขชุดเดียวกัน
