# 5.5 REST API vs MCP: เลือกใช้เมื่อไหร่

> ระดับ: 🔴 Advanced

คำถามที่ dev สาย Tableau ถามเสมอ: "ก็มี REST API อยู่แล้ว ทำไมต้อง MCP?" — คำตอบ: **คนละงานกัน** และโปรเจกต์จริงมักใช้ทั้งคู่

## หลักคิดหนึ่งบรรทัด

> **มี LLM อยู่ใน loop ไหม?** มี → MCP / ไม่มี → REST API (หรือ VDS ตรง)

MCP ไม่ใช่ "REST API เวอร์ชันใหม่" — มันคือชั้นที่ทำให้ **AI ตัดสินใจเรียก** ความสามารถต่าง ๆ ได้เอง ถ้าโปรแกรมของคุณรู้อยู่แล้วว่าจะทำอะไร (deterministic) การผ่าน AI มีแต่เพิ่ม cost + ความไม่แน่นอน

## ตารางตัดสินใจ

| งาน | ใช้อะไร | เหตุผล |
|---|---|---|
| Backup workbook ทุกคืน | REST API | ขั้นตอนตายตัว ไม่ต้องคิด |
| สร้าง user 200 คนจาก CSV | REST API | Batch deterministic |
| Embed dashboard ในเว็บ | Embedding API | คนละเรื่องกับทั้งคู่ |
| ดึงข้อมูลเข้า pipeline ETL | VDS / REST ตรง | โปรแกรมรู้ query ล่วงหน้า |
| "ถามอะไรก็ได้กับข้อมูล" | **MCP** | ไม่รู้ล่วงหน้าว่า user จะถามอะไร |
| รายงานสรุป + คำวิเคราะห์ภาษาคน | **MCP + Claude API** | ต้องการการตีความ ไม่ใช่แค่ตัวเลข |
| Agent ตรวจข้อมูลแล้วตัดสินใจเจาะต่อ | **MCP** | ขั้นถัดไปขึ้นกับผลขั้นก่อน |

## เห็นภาพด้วยงานเดียวกันสองวิธี

โจทย์: "ทุกเช้าส่งยอดขายเมื่อวานเข้า LINE กลุ่มผู้บริหาร"

**แบบ REST/VDS ตรง (ไม่มี AI):**

```javascript
const total = await vdsQuery(DS_LUID, FIXED_QUERY);   // query เดิมทุกวัน
await sendLine(`ยอดขายเมื่อวาน: ${fmt(total)} บาท`); // template ตายตัว
```

ถูกมาก (ไม่มี token cost), เร็ว, ผลเหมือนเดิม 100% — **ถ้าโจทย์แค่นี้ อย่าใช้ AI**

**แบบ MCP + Claude (มี AI):**

```
"ยอดขายเมื่อวานเท่าไหร่ เทียบค่าเฉลี่ย 7 วัน ถ้าผิดปกติเกิน 15%
 ให้เจาะหาสาเหตุจากมิติ region/channel แล้วเขียนสรุป 3 บรรทัด
 ภาษาผู้บริหาร"
```

ตัวเลขเดิมทุกวันแต่ **บทวิเคราะห์ปรับตามสถานการณ์** — วันปกติสรุปสั้น วันผิดปกติเจาะให้เอง — นี่คืองานที่ REST ตรงทำไม่ได้

ข้อสังเกต: เวอร์ชัน AI แพงกว่า (token) และมีความแปรปรวน — คุ้มเมื่อ "การตีความ" มีมูลค่า ไม่คุ้มเมื่อต้องการแค่ตัวเลข

## Pattern ผสมที่ใช้จริงบ่อยสุด

ระบบ production ที่ดีมักหน้าตาแบบนี้:

```
[ส่วน deterministic]                    [ส่วน AI]
REST API: เช็ค extract refresh สำเร็จ?  ──ถ้าสำเร็จ──►  MCP+Claude: วิเคราะห์+เขียนสรุป
REST API: ส่งผลลัพธ์ออก (LINE/email)   ◄──────────────  ได้ข้อความกลับมา
```

หลักการ: **โครงและ plumbing ใช้ REST (นิ่ง ถูก ตรวจง่าย) / การวิเคราะห์และภาษาใช้ MCP+AI** — อย่าให้ AI ทำงานที่ if-else ทำได้

## Cheat Sheet ภาพรวม API ฝั่ง Tableau

| API | หน้าที่ | MCP ใช้เบื้องหลังไหม |
|---|---|---|
| REST API | จัดการ content/users/permissions | ✅ (กลุ่ม workbook, search) |
| VizQL Data Service | query ข้อมูลจาก published DS | ✅ (query-datasource) |
| Metadata API (GraphQL) | โครงสร้าง/lineage ของข้อมูล | ✅ (list-fields, read-metadata) |
| Pulse API | metrics + insights | ✅ (กลุ่ม Pulse) |
| Embedding API | ฝัง viz ในเว็บ | ❌ คนละงาน |
| Hyper API | สร้าง/อ่านไฟล์ .hyper | ❌ คนละงาน |

มุมมองนี้ทำให้เห็นว่า MCP คือ "หน้ากาก AI-friendly" ครอบ API เดิม 4 ตัวแรก — ความสามารถอะไรที่ MCP ยังไม่ expose คุณยิง API ตรงเสริมได้เสมอ (และถ้าอยากให้ AI ใช้ได้ด้วย → ห่อเป็น custom tool ตามบท 5.4)
