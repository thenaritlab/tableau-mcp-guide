# 5.7 Agentic Workflows: Multi-step Agent + Claude Code

> ระดับ: 🔴 Advanced | บทสุดท้ายของ Part 5 — รวมทุกอย่างเข้าด้วยกัน

## จาก "ถาม-ตอบ" สู่ "มอบหมายงาน"

ทุกบทที่ผ่านมาคือ pattern ถาม→ตอบ — **agentic workflow** ต่างออกไป: มอบ "เป้าหมาย" แล้วให้ AI วางแผน ทำหลายขั้น ตรวจผลตัวเอง จนงานเสร็จ

```
ถาม-ตอบ:  "ยอดขายเดือนนี้เท่าไหร่"                    → 1-2 tool calls
Agentic:  "ตรวจสุขภาพข้อมูลทุก data source ใน project
           Sales แล้วเขียนรายงาน พร้อมจัดลำดับปัญหา"     → วางแผนเอง 20+ tool calls
```

ความจริงคุณเห็น agentic มาแล้วตั้งแต่บท 3.4 (คำสั่งเดียว AI ต่อหลาย tool) — บทนี้ทำให้มัน **ใหญ่ขึ้น เชื่อถือได้ขึ้น และรันเองได้**

## หลักออกแบบงาน agentic ให้เวิร์ก

### 1. เป้าหมายชัด + เกณฑ์ความสำเร็จชัด

```
❌ "ช่วยดูข้อมูลหน่อยว่าโอเคไหม"
✅ "ตรวจทุก data source ใน project Sales ตามเกณฑ์:
    (a) field สำคัญ (Sales, Order Date, Region) มี null เกิน 5% ไหม
    (b) ข้อมูลล่าสุดเก่ากว่า 2 วันไหม
    (c) ยอดรวมเดือนล่าสุดเบี่ยงจากค่าเฉลี่ย 3 เดือนเกิน 30% ไหม
    เสร็จแล้วสรุปเป็นตาราง: DS | เกณฑ์ที่ตก | ความรุนแรง | ข้อเสนอ"
```

### 2. ให้แผนก่อนลงมือ (สำหรับงานใหญ่)

```
"ก่อนเริ่ม เขียนแผนขั้นตอนมาให้ดูก่อน ฉันอนุมัติแล้วค่อยทำ"
```

ได้ตรวจ logic ก่อนเปลือง tool calls จริง — และ AI ที่เขียนแผนเองมักทำตามแผนได้ดีกว่า

### 3. กำหนดงบและทางหนีไฟ

จากบท 5.3: จำกัดรอบ loop, จำกัดขนาดผล, และสั่งไว้ว่า *"ถ้าติดขัดเกิน 3 ครั้งกับขั้นไหน ให้ข้ามและบันทึกไว้ในรายงาน อย่าวนต่อ"*

## Claude Code + Tableau MCP: คู่ที่ทรงพลังเป็นพิเศษ

**Claude Code** (agentic coding tool ของ Anthropic — รันใน terminal) ต่อ MCP ได้เหมือน Claude Desktop:

```bash
claude mcp add tableau -e SERVER=https://... -e SITE_NAME=... \
  -e PAT_NAME=... -e PAT_VALUE=... \
  -- npx -y @tableau/mcp-server@latest
```

ทำไมคู่นี้พิเศษ? เพราะ Claude Code มี **มือครบ**: Tableau MCP (ดึงข้อมูล) + เขียน/รันโค้ด + อ่านเขียนไฟล์ + git — งานที่เกินกำลังแชทปกติกลายเป็นไปได้:

### ตัวอย่างงานจริง 1: Documentation Factory แบบอัตโนมัติเต็มรูป

```
"สำหรับทุก data source ใน project Sales: ดึง metadata, สร้าง data
dictionary เป็นไฟล์ markdown แยกตัวละไฟล์ในโฟลเดอร์ docs/,
สร้าง index.md รวมลิงก์, แล้ว git commit"
```

(นี่คือบท 4.4 เวอร์ชันที่ไม่ต้องนั่ง copy ผลจากแชทเอง — เขียนไฟล์ + commit ให้เสร็จ)

### ตัวอย่างงานจริง 2: วิเคราะห์เกินกำลัง VDS

```
"ดึงยอดขายรายวัน 2 ปีจาก data source มาเก็บเป็น CSV แล้วเขียน Python
ทำ seasonal decomposition + forecast 3 เดือน สร้างกราฟ บันทึกเป็น
report.html"
```

MCP ดึงข้อมูล → Claude Code เขียนและ**รัน**สคริปต์วิเคราะห์จริง — สถิติหนัก ๆ ที่ VDS/LLM ทำเองไม่ได้ ใช้ Python ทำ ผลแม่นเพราะคำนวณจริงไม่ใช่ AI ประมาณ

### ตัวอย่างงานจริง 3: สร้างชุดทดสอบ RLS (จากบท 4.2) อัตโนมัติ

```
"เขียนสคริปต์ทดสอบ RLS: ยิง VDS ด้วย PAT ของ user ทดสอบ 2 คน
รัน test case ทั้ง 4 จากไฟล์ rls-test-plan.md แล้วสรุปผลเป็นตาราง
pass/fail"
```

ได้ regression test ที่รันซ้ำได้ทุกครั้งที่แก้ data source — หลักฐาน audit ชั้นดี

## Scheduled Agent: งานประจำที่รันเอง

ผูกทุกอย่างเข้า cron/scheduler:

```
┌─ ทุกวัน 07:00 ──────────────────────────────────────────┐
│ 1. script (REST) เช็ค extract refresh เมื่อคืนสำเร็จไหม     │
│ 2. สำเร็จ → เรียก agent (API+MCP): ตรวจสุขภาพข้อมูล 3 เกณฑ์ │
│ 3. ปกติ   → ส่ง LINE 1 บรรทัด "✅ ข้อมูลพร้อมใช้"           │
│    ผิดปกติ → agent เจาะสาเหตุต่อ → ส่งรายงานเต็ม + tag ทีม  │
└─────────────────────────────────────────────────────────┘
```

หลัก REST-for-plumbing / AI-for-analysis จากบท 5.5 ทำงานเต็มรูปแบบตรงนี้

## ข้อควรระวังของ agentic (สำคัญกว่าตอนถาม-ตอบมาก)

1. **Cost scale ตามความทะเยอทะยาน** — งาน 30 tool calls ทุกชั่วโมง ≠ ทุกวัน คิด token budget ก่อนตั้ง schedule
2. **สิทธิ์ต่ำสุดยิ่งสำคัญ** — agent ที่รันเองไม่มีคนดู ยิ่งต้องล็อก `INCLUDE_TOOLS` เหลือ read-only เท่าที่ใช้
3. **ตรวจ output ช่วงแรกเสมอ** — รัน agent ใหม่แบบมีคนอ่านผล 1-2 สัปดาห์ก่อนปล่อยเชื่อสนิท
4. **เก็บ audit log ทุก run** — tool calls + ผลลัพธ์ ลงไฟล์/DB — วันที่ผู้บริหารถามว่า "เลขนี้มายังไง" คุณจะขอบคุณตัวเอง
