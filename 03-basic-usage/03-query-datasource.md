# 3.3 Query Data Source ด้วยภาษาธรรมชาติ

> ระดับ: 🟢 Basic | บทที่ใช้งานจริงบ่อยที่สุดในคู่มือนี้

## เข้าใจกลไกก่อน: จากคำพูด → VDS Query

เมื่อคุณถาม *"ยอดขายรายภาคปี 2026"* Claude จะประกอบ query ประมาณนี้ส่งให้ VDS:

```json
{
  "fields": [
    { "fieldCaption": "Region" },
    { "fieldCaption": "Sales", "function": "SUM" }
  ],
  "filters": [
    { "field": { "fieldCaption": "Order Date" },
      "filterType": "DATE", "periodType": "YEARS", ... }
  ]
}
```

เข้าใจแค่นี้พอสำหรับตอนนี้ (โครงสร้างเต็มอยู่ Part 5.6): **ทุกคำในคำถามของคุณถูกแปลงเป็น field + aggregation + filter** — ดังนั้นยิ่งคำถามระบุ 3 อย่างนี้ชัด ผลลัพธ์ยิ่งแม่น

## สูตรตั้งคำถามให้ query แม่น

```
[ตัวชี้วัด] + [มุมมอง/จัดกลุ่ม] + [เงื่อนไข/ช่วงเวลา] + [รูปแบบผลลัพธ์]
```

| ส่วน | ตัวอย่าง |
|---|---|
| ตัวชี้วัด | ยอดขาย (SUM), จำนวนออเดอร์ (COUNT), กำไรเฉลี่ย (AVG) |
| มุมมอง | รายภาค, รายเดือน, ต่อ segment ลูกค้า |
| เงื่อนไข | ปี 2026, เฉพาะหมวด Furniture, ยอด > 10,000 |
| รูปแบบ | top 10, เรียงมากไปน้อย, เป็นเปอร์เซ็นต์, ทำตาราง |

**เทียบกันชัด ๆ:**

❌ คลุมเครือ: "ขายดีไหมช่วงนี้"
✅ ชัดเจน: "ยอดขายรวมเดือน ส.ค. 2026 เทียบ ก.ค. 2026 เปลี่ยนกี่ % และหมวดไหน โต/หด แรงสุด"

## ตัวอย่าง Query ตามประเภทงาน

### เปรียบเทียบช่วงเวลา (พบบ่อยสุดในงานจริง)

```
เทียบยอดขายรายเดือน ปี 2026 vs 2025 ทำเป็นตาราง
มีคอลัมน์ %เปลี่ยนแปลง และไฮไลต์เดือนที่ติดลบ
```

### หาตัวผิดปกติ

```
เดือนไหนใน 12 เดือนล่าสุดที่ยอดขายเบี่ยงจากค่าเฉลี่ยเกิน 20%
ทั้งบวกและลบ พร้อมเดาสาเหตุจากมิติอื่นที่มีในข้อมูล
```

### Contribution / สัดส่วน

```
ลูกค้า top 10 คิดเป็นกี่ % ของยอดขายรวม
และถ้าตัด top 10 ออก ยอดที่เหลือโตขึ้นหรือลดลงเทียบปีก่อน
```

### เจาะจาก aggregate ลง detail

```
คุณ: ภาคไหนกำไรต่ำสุด
Claude: [ตอบ: ภาคกลาง]
คุณ: ในภาคกลาง จังหวัดไหนฉุดกำไรมากสุด แล้วสินค้าตัวไหนในจังหวัดนั้น
```

## ข้อจำกัดที่ต้องรู้ (สำคัญมาก)

### 1. Query ได้เฉพาะ **Published Data Source**

Data source ที่ฝังใน workbook (embedded) query ไม่ได้ — ถ้า AI บอกหาไม่เจอทั้งที่เห็นใน dashboard ให้ publish data source แยกก่อน (Tableau Desktop: คลิกขวา data source → Publish to Server)

### 2. คำนวณตามที่ data source นิยามไว้

Calculated field ที่สร้างไว้ **ระดับ data source** ใช้ได้เลย แต่ calculated field ที่สร้างใน workbook — MCP ไม่เห็น ถ้าตัวเลขสำคัญ (เช่นสูตร margin เฉพาะบริษัท) แนะนำย้ายไปนิยามที่ data source เพื่อให้คน + AI ใช้สูตรเดียวกัน

### 3. ข้อมูลใหญ่ = ถามให้แคบ

VDS ไม่เหมาะกับการดึงข้อมูลดิบล้านแถว — ระบุ filter, top N, หรือ aggregate เสมอ ถามกว้างเกินอาจช้าหรือถูกตัด

### 4. RLS ทำงานตามสิทธิ์ของ credential ที่ MCP ใช้

ถ้าใช้ PAT — เห็นเท่าที่เจ้าของ PAT เห็น / Hosted MCP + OAuth — เห็นเท่าที่ user ที่ login เห็น (เจาะลึก + วิธีทดสอบใน Part 4.2)

## เทคนิคตรวจสอบความถูกต้อง

ก่อนเชื่อตัวเลขไปใช้งานสำคัญ:

1. **ขอ query:** "แสดง query ที่ใช้ให้ดูหน่อย ใช้ field ไหน filter อะไร"
2. **Cross-check 1 จุด:** เทียบตัวเลขเดียวกันกับ dashboard ที่มีอยู่ 1 ค่า ถ้าตรง ที่เหลือมักตรง
3. **ระวังคำกำกวมในข้อมูลไทย:** "ยอดขาย" มีทั้ง field ก่อน/หลัง VAT? "วันที่" ใช้ order date หรือ ship date? — บอก AI ชัด ๆ ครั้งเดียวต้นบทสนทนา เดี๋ยวมันจำใช้ทั้งแชท
